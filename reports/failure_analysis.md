## Intent classification errors

- **Layer:** model + taxonomy
- **Scope:** LLM classifier (gpt-oss-120b) on the 100 blind-human golden cases
- **Count:** 40 / 100
- **Observed:** 40 of 100 blind cases misclassified; 32 of those errors had self-reported confidence >= 0.90, so the confidence threshold (0.75) does not catch them.
- **Likely cause:** Self-reported LLM confidence is uncalibrated; the classifier sees only the opening tweet while the labeler saw the whole conversation.
- **Hypothesis / fix:** Calibrate confidence on dev (reliability curve) or replace it with retrieval-agreement signals; give the classifier the thread context the labeler had.

## Intent boundary ambiguity

- **Layer:** taxonomy
- **Scope:** LLM errors on the blind 100, grouped into unordered intent pairs
- **Count:** 14 / 40
- **Observed:** Most confused pairs: journey_disruption_complaint / service_status_delay_enquiry (5); chitchat_non_support / praise_positive_feedback (4); service_status_delay_enquiry / ticket_booking_query (3); customer_service_complaint / ticket_booking_query (2). Independently, the candidate taxonomy disagrees with the final gold intent on 131 of 250 golden cases.
- **Likely cause:** Several intents describe the same tweet from different angles (a delayed train is both a status question and a complaint); the taxonomy came from soft clusters (silhouette about 0.05).
- **Hypothesis / fix:** Define intents by the action the brand must take (live info / compensation / acknowledge) and add decision rules for the top pairs; re-label only after freezing the new definitions.

## Retrieval finds the topic but not the handling

- **Scope:** proxy retrieval evaluation on 857 dev queries (labels are heuristic, not human)
- **Count:** 185 / 857
- **Observed:** 185 queries had no relevant case in the top 5; 178 of them retrieved the same intent but a different resolution type.

## Over-escalation built into the policy

- **Layer:** policy
- **Scope:** hard rules applied to the GOLD intent of the blind 100 (perfect-classifier oracle)
- **Count:** 40 / 81
- **Observed:** Of 81 blind cases a human said need not escalate, 40 would still be escalated by a hard rule even with perfect classification (intent rule 37, sensitive wording 7, low-information 1; a case can fire several).
- **Likely cause:** Whole intents are blocked (status, disruption, Delay Repay, complaints, unclear), and the sensitive-word list matches words like 'wheelchair' or 'refund' even in praise or simple questions.
- **Hypothesis / fix:** Gate on the action needed rather than the intent (a timetable question is not a live-status question), and scope sensitive words to complaints; tune on dev, not golden.

## Potential unsafe auto-handles

- **Layer:** policy
- **Scope:** blind 100 (oracle) + the partial agent run
- **Count:** 3 / 19
- **Observed:** 3 of 19 blind cases that should escalate are not caught by any hard rule; only the soft checks (confidence, evidence, grounding) stand between them and an auto-reply. Observed in the partial agent run: 0 unsafe auto-handles out of 11 cases.
- **Likely cause:** Escalation-worthy cases that look like routine intents (e.g. a booking question that actually needs an account lookup) slip past intent-level rules.
- **Hypothesis / fix:** Measure auto-handle precision on the full 50-case slice, then add the specific triggers found (account/booking-reference requests) as rules.
